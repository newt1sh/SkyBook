# Вимоги до проєкту SkyBook

## 1. Призначення

SkyBook — вебзастосунок для пошуку, перегляду та бронювання авіаквитків. Система дозволяє користувачам знаходити доступні авіарейси за напрямком, переглядати інформацію про рейси, обирати квитки та оформлювати бронювання.

## 2. Ролі користувачів

- **Відвідувач** — перегляд доступних авіарейсів, пошук за напрямком, перегляд інформації про рейси та бронювання квитків.
- **Адміністратор** — додавання, редагування та видалення інформації про аеропорти, авіарейси й квитки.

## 3. Сутності предметної області

| Сутність | Атрибути |
|---|---|
| Airport | id, name, city, country, code |
| Flight | id, departure_airport_id, arrival_airport_id, departure_time, arrival_time, price, status |
| Passenger | id, first_name, last_name, email, phone |
| Ticket | id, flight_id, passenger_id, seat, price, status, booking_date |

## 4. Зв'язки між сутностями

- Airport 1 — ∞ Flight (аеропорт може бути місцем відправлення або прибуття багатьох рейсів).
- Flight 1 — ∞ Ticket (один авіарейс може мати багато квитків).
- Passenger 1 — ∞ Ticket (один пасажир може мати декілька квитків).

## 5. Сторінки вебзастосунку

1. `/` — головна сторінка: інформація про сервіс, форма пошуку авіарейсів та популярні напрямки.
2. `/flights` — перелік авіарейсів із можливістю пошуку та фільтрації.
3. `/flight/:id` — картка авіарейсу: інформація про маршрут, час відправлення, прибуття та вартість.
4. `/booking` — форма бронювання квитка з введенням особистих даних пасажира.
5. `/contacts` — контактна інформація та форма зворотного зв'язку.

## 6. Функціональні вимоги

F1. Користувач може шукати авіарейси за містом відправлення та призначення.

F2. Система відображає список доступних рейсів відповідно до параметрів пошуку.

F3. Користувач може переглядати детальну інформацію про вибраний авіарейс.

F4. Система дозволяє оформити бронювання квитка через спеціальну форму.

F5. Форма бронювання перевіряє правильність введення імені, прізвища, номера телефону та електронної пошти.

F6. Інформація про бронювання зберігається в базі даних.

F7. Адміністратор може керувати інформацією про авіарейси та аеропорти.

## 7. Нефункціональні вимоги

N1. Інтерфейс вебзастосунку повинен бути адаптивним для екранів шириною від 360 px.

N2. Інтерфейс повинен бути зрозумілим і зручним для користувачів.

N3. Дані повинні зберігатися в реляційній базі даних.

N4. Форми повинні перевіряти введені користувачем дані перед їх збереженням.

N5. Вебзастосунок повинен коректно працювати в сучасних браузерах.

N6. Система повинна забезпечувати захист персональних даних пасажирів.
